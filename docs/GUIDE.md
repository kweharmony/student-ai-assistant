## 1. Что это за проект

**MindeSync (Student AI Assistant)** — платформа, которая превращает запись лекции
в готовые учебные материалы. Весь путь выглядит так:

1. Студент загружает аудио или видео лекции.
2. Запись локально распознаётся в текст с помощью **Whisper** — на отдельной
   рабочей машине (воркере), а не на сервере, потому что у сервера нет видеокарты.
3. Текст можно почистить AI-фильтром (убрать оговорки, слова-паразиты, ошибки
   распознавания) и превратить с помощью **LLM** в конспекты, списки терминов,
   вопросы для самопроверки, шпаргалки и развёрнутые объяснения.
4. Результат экспортируется в **PDF, DOCX, TXT или Markdown**.
5. Лекцию можно опубликовать в общий **каталог дисциплин** (после модерации) и
   рисовать совместные **доски** (на базе Excalidraw).

Коротко: загрузил лекцию → получил конспект → поделился с группой.

## 2. Кто им пользуется (роли)

В системе три роли и один дополнительный флаг.

| Роль | Что может |
|------|-----------|
| **Студент** | Загружать лекции, транскрибировать, генерировать материалы для себя, отправлять заявки на публикацию в каталог. |
| **Преподаватель** | То же, что студент. Отдельных «учительских» функций нет — роль влияет в основном на профиль и отображение. |
| **Администратор** | Полный доступ: управление пользователями, контентом, модерация всего каталога, выдача тарифов, блокировки. |

**Староста** (`is_group_head`) — это не отдельная роль, а флаг поверх студента.
Староста становится **модератором каталога в пределах своего потока**: одобряет
публикации лекций и заявки на генерацию материалов от одногруппников. Назначить
старосту может только администратор.

Главный принцип прав: **администратор видит и правит все потоки, староста — только
свой**.

## 3. Как этим пользоваться — сценарии

### Базовый сценарий: лекция → конспект

1. Зарегистрируйтесь и войдите. Логин система генерирует сама на основе вашей
   почты и показывает его при регистрации — запомните его, входить нужно по логину.
2. Откройте раздел **Транскрайбер** и загрузите файл лекции (аудио или видео,
   до 100 МБ).
3. Дождитесь, пока воркер распознает запись. Это происходит не мгновенно —
   задача встаёт в очередь и обрабатывается на машине с Whisper.
4. При желании примените **AI-фильтр**, чтобы почистить текст.
5. В разделе лекций выберите нужный материал: конспект, термины, вопросы,
   подробный конспект или шпаргалку — и запустите генерацию.
6. Сохраните результат в PDF, DOCX, TXT или Markdown.

### Сценарий публикации в каталог

1. Студент отправляет заявку на публикацию своей лекции.
2. Староста потока (или администратор) видит заявку, при необходимости правит
   данные (дисциплина, лектор, курс, семестр) и одобряет либо отклоняет (при
   отклонении обязателен комментарий).
3. После одобрения лекция появляется в общем каталоге и становится доступна всем
   на чтение.

> Важно: после публикации право редактировать текст лекции переходит к модератору
> потока — сам студент-владелец больше не может сохранять правки в опубликованную
> лекцию. Это сделано, чтобы за общий контент отвечал модератор.

### Сценарий совместной доски

1. Создайте доску в разделе **Доски**.
2. Включите шаринг и выберите режим: **просмотр** или **редактирование**.
3. Поделитесь ссылкой. По публичной ссылке доска открывается без входа в систему;
   в режиме редактирования несколько человек рисуют одновременно в реальном времени.

## 4. Возможности по разделам кабинета

Личный кабинет разбит на разделы (видимость зависит от роли):

- **Профиль** — данные пользователя, аватар (картинка или эмодзи), смена пароля,
  выбор потока, карточка тарифа с остатком лимитов.
- **Транскрайбер** — загрузка записи и запуск распознавания, базовая чистка текста.
- **Обработка текста** — работа с текстом лекции, объяснение фрагментов через LLM.
- **Лекции** — список ваших лекций, генерация материалов (можно запускать несколько
  разных материалов параллельно), AI-фильтр, повторная транскрибация, отправка на
  публикацию.
- **Каталог** — общий каталог опубликованных лекций по дисциплинам.
- **Модерация каталога** (староста/админ) — одобрение заявок на публикацию и на
  генерацию материалов, управление структурой каталога своего потока.
- **Админ-панель** (только админ) — пользователи, контент, статистика, очередь
  задач, выдача тарифов, блокировки.
- **Доски** — совместные полотна Excalidraw.

## 5. Как всё устроено внутри (архитектура простыми словами)

Система состоит из нескольких отдельных частей, каждая отвечает за своё:

| Компонент | Что делает |
|-----------|-----------|
| **Frontend** (React) | Сайт и личный кабинет, с которым работает пользователь. |
| **Backend** (FastAPI) | Сервер с основной бизнес-логикой: авторизация, лекции, каталог, очередь задач, модерация. |
| **PostgreSQL** | База данных — здесь хранится всё (пользователи, лекции, тексты, каталог). |
| **Redis** | Вспомогательное хранилище: «чёрный список» токенов после выхода и синхронизация совместных досок между серверами. Опционально — без него приложение работает, но эти две функции отключаются. |
| **ML-слой** | Промпты и вызовы LLM для генерации материалов и чистки текста. |
| **Воркер** | Отдельная программа на машине с видеокартой, которая распознаёт аудио через Whisper. В Docker не входит — запускается отдельно. |
| **PDF-сервис** (Node.js) | Превращает Markdown в PDF (через Chromium и KaTeX для формул) и в DOCX (через Pandoc). |
| **Nginx** | Reverse-proxy перед всем этим в Docker-варианте. |

### Почему транскрибация вынесена в воркер

Распознавание речи Whisper'ом требует производительной видеокарты. У сервера её
нет, поэтому он лишь **складывает задачи в очередь**, а отдельные машины-воркеры
их разбирают: забирают задачу → скачивают аудио → распознают → присылают текст
обратно. Если воркер «завис», сервер через некоторое время автоматически вернёт
его задачу в очередь, чтобы её взял кто-то другой.

### Как хранятся данные и удаление

- Удаление почти везде **мягкое**: запись помечается удалённой, но физически
  остаётся. Это защищает от случайной потери данных.
- **Аудиофайлы живут 7 дней**, потом автоматически удаляются с диска (сами тексты
  и материалы остаются). Аудио — это самое тяжёлое, и держать его вечно нет смысла.

### Авторизация

Вход по логину и паролю выдаёт JWT-токен. Токен передаётся двумя способами: в
заголовке запроса и в защищённой cookie. На фронтенде токен хранится только в
памяти (не в localStorage) — это защита от кражи через XSS; после перезагрузки
страницы сессия восстанавливается из cookie.

## 6. Какие модели используются

> **Важное уточнение.** В коде и в `.env` переменные исторически названы
> `DEEPSEEK_*` (например `DEEPSEEK_MODEL`), но **фактически в качестве основной
> модели сейчас используется Qwen** через провайдера VseLLM. Название переменных —
> наследие, не путайтесь: смотрите на значение, которое реально прописано, а не на
> слово «deepseek» в имени.

Используются три вещи:

- **Whisper** — локальное распознавание речи на воркере (модель `base`/`medium` и
  т.п. на выбор).
- **Qwen через VseLLM** (переменные `DEEPSEEK_*`) — основной генератор учебных
  материалов: конспекты, термины, вопросы, шпаргалки, подробные конспекты.
- **Отдельный LLM через PolzaAI** (переменные `POLZA_*` / `DIAGRAM_*`) — для
  функции «объяснить фрагмент» и построения диаграмм.

Все обращения к LLM идут через OpenAI-совместимый протокол, поэтому сменить
провайдера или модель можно, просто поменяв URL, ключ и название модели в `.env` —
код трогать не нужно.

## 7. Тарифы и лимиты генераций

Чтобы ограничить расходы на платный LLM-API, генерация материалов ограничена
квотой. Есть два независимых счётчика со **скользящим окном в 30 дней**:

| Счётчик | Что в него входит | free | pro |
|---------|-------------------|------|-----|
| **generation** | Генерация заметок (любой режим) **и** AI-фильтр своей лекции — общий счётчик. | 5 | 15 |
| **explain** | Объяснение фрагмента текста. | 10 | 30 |

Как это работает на практике:

- Лимит тратится только когда вы генерируете в **своей личной** лекции. Действия
  администратора и модераторская генерация в чужих опубликованных лекциях лимит
  не расходуют.
- Если генерация провалилась (ошибка LLM **или** модель вернула пустой ответ) —
  слот возвращается обратно, за бесполезный результат не списывают.
- Когда лимит исчерпан, эндпоинт отвечает кодом **429** — фронтенд показывает это
  понятным сообщением и счётчиком остатка.
- Тариф **pro** выдаёт только администратор (по умолчанию на 30 дней). После
  истечения срока пользователь снова считается как **free**.

Значения лимитов настраиваются в `.env` (`QUOTA_GEN_FREE/PRO`,
`QUOTA_EXPLAIN_FREE/PRO`).

## 8. Запуск проекта

Есть два пути. Подробные команды и проверка — в [README.md](../README.md), здесь
кратко суть.

### Вариант 1. Docker Compose (весь стек одной командой)

Поднимает backend, frontend, PostgreSQL, Redis, PDF-сервис и nginx:

```bash
docker compose up --build -d
```

После старта:
- сайт — `http://localhost`
- API — `http://localhost:8000`
- документация API — `http://localhost:8000/docs`

> Воркер транскрибации в Docker **не входит** — его всегда поднимают отдельно на
> машине с видеокартой (см. раздел 10).

### Вариант 2. Локальный запуск

```powershell
setup.bat   # установка зависимостей (Windows; на Unix — ./setup.sh)
run.bat     # запуск backend + frontend
```

Backend поднимется на `http://localhost:8000`, frontend — на `http://localhost:3000`.
PDF-сервис и воркер при необходимости запускаются отдельно.

### Первый администратор

После первого запуска нужно создать админа:

```powershell
.\.venv\Scripts\python -m scripts.create_admin   # спросит логин, email, пароль
```

Через публичную регистрацию стать администратором нельзя — только через скрипт или
руками другого админа.

## 9. Настройка окружения

Скопируйте `.env.example` в `.env` и заполните значения. Самое важное:

| Переменная | Зачем |
|-----------|-------|
| `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL` | Основной LLM (фактически Qwen через VseLLM — см. раздел 6). |
| `POLZA_*`, `DIAGRAM_*` | LLM для «объяснить фрагмент» и диаграмм. |
| `DATABASE_URL`, `POSTGRES_*` | Подключение к PostgreSQL. |
| `SECRET_KEY` | Секрет для подписи JWT. Обязательно поменять в проде. |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | Срок жизни токена (по умолчанию 1440 = 24 часа). |
| `COOKIE_SECURE` | `true` за HTTPS — обязательно в проде. |
| `REDIS_URL` | Redis. Опционально, но без него не работают выход из сессии (revoke) и синхронизация досок между серверами. |
| `CORS_ORIGINS` | Разрешённые домены фронтенда. |
| `REACT_APP_API_URL` | URL backend, **вшивается в сборку фронтенда**. |
| `WORKER_API_KEYS` | Ключи воркеров в формате `Имя:ключ,Имя2:ключ2`. |
| `QUOTA_*` | Лимиты тарифов (см. раздел 7). |

## 10. Воркер транскрибации

Воркер — это отдельная программа, которая запускается на рабочей станции (лучше с
NVIDIA GPU) и разбирает очередь распознавания. Подробный гайд —
[WORKER_GUIDE.md](WORKER_GUIDE.md), запуск на Windows — [WORKER_RUN.md](../worker/WORKER_RUN.md).

**Что делает воркер по кругу:** спрашивает у сервера задачу → скачивает аудио →
распознаёт через Whisper → отправляет текст обратно. Пока идёт распознавание,
посылает «сердцебиение» (heartbeat), чтобы сервер знал, что он жив.

**Запуск (кратко):**

```powershell
cd worker
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python tray_app.py
```

Воркер живёт в системном трее:
- **зелёная иконка** — включён, берёт новые задачи;
- **серая иконка** — на паузе.

Конфигурация — в `worker/config.json`: адрес сервера (`SERVER_URL`), ключ
(`API_KEY`, должен совпадать с одним из `WORKER_API_KEYS` на сервере), имя воркера,
модель Whisper и устройство (`auto` / `cpu` / `cuda`).

Для ускорения на видеокарте нужно отдельно поставить PyTorch с поддержкой CUDA в
окружение воркера — иначе распознавание идёт на CPU и работает медленнее.

## 11. Частые проблемы

**Воркер не показывается как активный.** Проверьте `worker/config.json` и что ключ
совпадает с серверным. Учтите: если в очереди нет задач, список активных воркеров
может быть пустым, даже когда воркер запущен — это нормально.

**`Invalid worker API key`.** Ключ в `API_KEY` воркера не совпадает с ключом на
сервере в `WORKER_API_KEYS`. Должно совпадать точь-в-точь.

**Медленная транскрибация.** Поставьте PyTorch с CUDA, если есть NVIDIA GPU, и/или
используйте модель Whisper полегче (`small`, `medium`).

**Backend не стартует.** Проверьте `.env`, доступность PostgreSQL и
`DATABASE_URL`, посмотрите вывод `uvicorn`.

**Frontend не стартует.** Переустановите `node_modules`, проверьте
`REACT_APP_API_URL`, освободите порт 3000.

**Выход из аккаунта «не работает» (старый токен ещё валиден).** Скорее всего не
поднят Redis — без него отзыв токенов при logout не действует.

**Ошибка PowerShell при активации `.venv`.** Запускайте Python напрямую через путь,
без `Activate.ps1`:

```powershell
.\.venv\Scripts\python tray_app.py
```
