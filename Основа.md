
## 🎯 **Цель проекта (Vision)**

Создать интеллектуальный студенческий ассистент, который:
1. **Превращает аудио/текст в структурированные конспекты**.
2. **Помогает студенту эффективно управлять временем**, учитывая его реальную учебную нагрузку и приоритеты.

---

## 🧱 **Основные компоненты системы**

| Компонент | Описание | Ответственность |
|----------|--------|----------------|
| **Аутентификация и профиль** | Регистрация, логин, управление аккаунтом | Фронтенд + бэкенд |
| **Загрузка и хранение аудио/текста** | Поддержка MP3, WAV, PDF, DOCX и т.д. | Фронтенд + бэкенд |
| **Аудиотранскрибация** | Преобразование речи в текст | ML-спец по звуку |
| **Обработка текста (NLP)** | Извлечение ключевых терминов, суммаризация, расширение тем | ML-спец по тексту |
| **Генерация конспектов** | Формирование структурированного вывода (с заголовками, списками и т.д.) | ML-спец по тексту + бэкенд |
| **Тайм-менеджмент (опционально)** | Расчёт оптимального расписания на основе ввода студента | Все (особенно ML-спец по тексту для логики + бэкенд) |
| **UI/UX интерфейс** | Интуитивный, минималистичный, ориентированный на студентов | Фронтенд |

## 🗺️ **Этапы реализации (Roadmap)**

### 🔹 **Этап 0: Подготовка и планирование (1–2 недели)**
- **Определить MVP (Minimum Viable Product)**:
  - Регистрация + загрузка аудио → транскрибация → редактирование/обработка текста → сохранение конспекта.
  - **Без тайм-менеджмента на первом этапе** — он пойдёт во вторую итерацию.
- **Выбрать стек технологий**:
  - **Frontend**: React + TypeScript (возможно, Next.js для SSR)
  - **Backend**: FastAPI / Django REST / Node.js
  - **База данных**: PostgreSQL (для структурированных данных) + S3/MinIO (для хранения файлов)
  - **ML**: Python, Whisper (для аудио), Transformers (HuggingFace) или LLM API (OpenAI, Mistral, Llama 3 и т.д.)
- **Настроить CI/CD, Git-репозиторий, задачи в Jira/Trello**

---

### 🔹 **Этап 1: MVP — Ядро обработки конспектов (4–6 недель)**

#### ✅ Задачи по ролям:

**1. Фронтенд + бэкенд:**
- [ ] Реализовать регистрацию/авторизацию (JWT или OAuth)
- [ ] Страница загрузки: drag & drop аудио/документов
- [ ] API для загрузки файлов → сохранение в хранилище
- [ ] Интерфейс для отображения транскрибированного текста
- [ ] Возможность выбрать шаблон обработки («Краткий конспект», «Выделить термины», «Объяснить сложные понятия»)
- [ ] Сохранение и экспорт (PDF/копировать в буфер)

**2. ML-спец по звуку:**
- [ ] Интеграция Whisper (open-source, работает офлайн, поддерживает русский)
- [ ] Предобработка аудио (нормализация громкости, удаление шума — опционально)
- [ ] API-эндпоинт `/transcribe` → возвращает текст

**3. ML-спец по тексту:**
- [ ] Подготовить шаблоны промптов для разных типов обработки:
  - `summarize`: «Сделай краткий конспект лекции...»
  - `extract_terms`: «Выдели ключевые термины и дай определения...»
  - `expand`: «Расширь объяснение темы X...»
- [ ] Выбор модели:
  - Локально: Mistral 7B, Llama 3 (если есть GPU)
  - Облачно: OpenAI GPT-4o-mini (дешевле, быстрее, поддержка русского)
- [ ] API-эндпоинт `/process` → принимает текст + тип → возвращает обработанный текст

> 💡 **Важно**: Используйте **prompt engineering** + **few-shot examples** для стабильного качества.

---

### 🔹 **Этап 2: Тайм-менеджмент (3–4 недели)**

#### Функционал:
- Студент вводит:
  - Расписание пар (дни/время/предметы)
  - Сложность предметов (1–10)
  - Дедлайны ДЗ/проектов
  - Личное время (сон, спорт, отдых)
- Система генерирует **недельный план** с блоками времени на:
  - Повторение конспектов
  - Выполнение ДЗ
  - Подготовку к экзаменам

#### Реализация:
- **Алгоритм**: Жадный + приоритизация по дедлайну и сложности
- **ИИ-улучшение**: Использовать LLM для генерации рекомендаций вида:  
  _«Поскольку у тебя завтра экзамен по физике (сложность 9), выдели 2 часа сегодня вечером на повторение конспекта №3»_
- **Интеграция с календарём**: Экспорт в Google Calendar / iCal

> ⚠️ **Совет**: Не пытайтесь сделать идеальный алгоритм с первого раза. Начните с простого правила:  
> **Время на предмет = (сложность × объём ДЗ) / оставшиеся дни до дедлайна**

---

### 🔹 **Этап 3: Улучшения и масштабирование (пост-MVP)**
- Поддержка нескольких языков
- Мобильное приложение (PWA или React Native)
- Коллаборативные конспекты (групповая работа)
- Интеграция с LMS (Moodle, Google Classroom)
- Аналитика: «Ты тратишь 70% времени на предметы с низким ROI»
- Обратная связь от студентов → fine-tuning моделей

---

## ⚠️ **Риски и как их избежать**
| Риск | Решение |
|------|--------|
| Whisper плохо распознаёт русскую речь с акцентом | Использовать fine-tuning на студенческих лекциях (собрать датасет) |
| LLM даёт неточные определения | Добавить RAG (Retrieval-Augmented Generation) — подтягивать данные из Википедии/учебников |
| Сервер не справляется с нагрузкой | Использовать очереди (Celery/RQ) + кэширование |
| Студенты не доверяют ИИ | Добавить возможность редактирования + «объяснение, почему так» |
