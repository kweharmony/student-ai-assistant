# 📄 **Отчёт проектного практикума**  
## **Тема проекта**:  

**«Разработка веб-платформы для автоматизированной обработки студенческих лекций и персонализированного тайм-менеджмента»**

---

## **1. Цель проекта**

**Разработать минимально жизнеспособный продукт (MVP) веб-платформы, позволяющий студенту загружать аудиозаписи лекций, автоматически транскрибировать их в текст, обрабатывать с помощью ИИ для получения структурированного конспекта, а также (в рамках расширенной функциональности) формировать персонализированный недельный план учёбы на основе введённых данных о расписании, сложности предметов и дедлайнах — в течение 10 недель командной работы при затратах не более 300 человеко-часов.**

> ✅ **Цель конкретна**:  
> — Есть чёткий функционал (транскрибация + обработка текста + тайм-менеджмент).  
> — Есть ограничение по времени (10 недель).  
> — Есть ограничение по ресурсам (300 человеко-часов).  
> — Есть критерий завершённости (рабочий MVP с UI и API).

---

## **2. Актуальность и проблематика**

Современные студенты сталкиваются с двумя ключевыми проблемами:
1. **Информационная перегрузка**: объём учебного материала растёт, но время на его усвоение ограничено. Многие записывают лекции на диктофон, но не переслушивают их из-за нехватки времени.
2. **Неэффективное управление временем**: студенты часто не могут объективно оценить, сколько времени нужно на подготовку к каждому предмету, что приводит к прокрастинации, стрессу и снижению академической успеваемости.

Существующие решения (например, Otter.ai, Notion AI) либо не адаптированы под учебный контекст, либо не учитывают индивидуальную учебную нагрузку. Наш проект заполняет этот пробел, объединяя **обработку учебного контента** и **интеллектуальное планирование времени** в одном инструменте.

---

## **3. Основные задачи проекта**

Для достижения цели необходимо решить следующие задачи:

### **3.1. Организационные**
- Сформировать команду из 3 участников с чётким распределением ролей.
- Разработать техническое задание и roadmap.
- Настроить систему контроля версий (Git), трекинг задач (Trello/Jira) и CI/CD.

### **3.2. Технические**
1. **Реализовать систему аутентификации и управления профилем пользователя**.
2. **Разработать интерфейс загрузки аудиофайлов и текстовых документов** (поддержка MP3, WAV, PDF, DOCX).
3. **Интегрировать модуль автоматической транскрибации речи в текст** на основе модели Whisper.
4. **Создать систему обработки текста с помощью ИИ**, включающую:
   - Генерацию краткого конспекта,
   - Извлечение и определение ключевых терминов,
   - Расширение сложных понятий.
5. **Реализовать модуль персонализированного тайм-менеджмента**, который:
   - Принимает данные о расписании, сложности предметов (1–10), дедлайнах ДЗ и личном времени,
   - Формирует недельный план с рекомендациями по распределению учебной нагрузки.
6. **Обеспечить экспорт результатов** (PDF, копирование в буфер, экспорт в календарь).

## **6. Технологический стек**

- **Frontend**: React + TypeScript + Tailwind CSS + Axios
- **Backend**: FastAPI (Python) + SQLAlchemy + JWT
- **База данных**: PostgreSQL
- **Хранение файлов**: MinIO (локальный S3-совместимый объектный storage)
- **Аудио-транскрибация**: OpenAI Whisper (large-v3, fine-tuned на русской речи при необходимости)
- **Обработка текста**: Llama 3 8B (локально) или GPT-4o-mini (через API)
- **Очереди задач**: Celery + Redis (для асинхронной обработки аудио)
- **Деплой**: Docker + nginx (локально или на VPS)

## 🔑 **Ключевые отличия и конкурентные преимущества нашего проекта**

### 1. **Уникальная интеграция двух больших задач**
> Большинство конкурентов решают **либо** проблему транскрибации (**Otter, Notta**), **либо** проблему обработки текста (**Notion, StudyMonkey**).  
> **Наш проект — единственный**, кто **связывает обработку учебного контента с персонализированным планированием времени**.

### 2. **Тайм-менеджмент, адаптированный под студента**
> Ни один из проанализированных продуктов **не учитывает**:
> - Сложность предметов по шкале,
> - Количество и срочность домашних заданий,
> - Личное время студента (сон, спорт, отдых).  
> Это **наш главный USP (Unique Selling Proposition)**.

### 3. **Полный контроль над данными и моделями**
> Использование **локальных open-source моделей** (Whisper, Llama 3) позволяет:
> - Работать без подписки,
> - Обеспечить конфиденциальность лекций,
> - Fine-tune под русскоязычную академическую речь.

### 4. **Фокус на учебный контекст**
> В отличие от **Otter.ai** и **Fireflies.ai**, созданных для бизнес-встреч , наш продукт:
> - Оптимизирован под структуру лекций (введение → теория → примеры → вывод),
> - Генерирует **учебно-ориентированные** конспекты, а не просто стенограммы.

## 🔑 Ключевые принципы этой структуры

1. **Разделение слоёв**  
   — Фронтенд не знает, как работает Whisper.  
   — ML-модули не зависят от FastAPI → их можно тестировать отдельно.

2. **Масштабируемость**  
   — Хочешь добавить мобильное приложение? Используй тот же API.  
   — Хочешь заменить OpenAI на Mistral? Меняй только `llm_processor.py`.

3. **Безопасность**  
   — `.env` хранит секреты, не попадает в Git.  
   — Пароли хешируются, JWT защищает эндпоинты.

4. **Удобство для команды**  
   — Фронтендер работает в `frontend/`, не лезет в Python.  
   — ML-специалист пишет в `ml/`, не трогает роуты.

5. **Готовность к облаку**  
   — Легко за1деплоить на Render, Railway, или VPS.  
   — Поддержка Docker — один `docker-compose up` и всё работает.
